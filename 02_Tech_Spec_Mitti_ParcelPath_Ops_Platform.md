## 5. Business logic

### 5.1 Metric formulas
| Metric | Formula |
|---|---|
| On-time % | delivered by `promisedBy` ÷ delivered |
| Failed % | orders with `outcome` starting `failed_` ÷ orders attempted |
| Damage per 10k | damage complaints ÷ orders delivered × 10,000 |
| Feed delay | `H1.start − M5.end`; split: website queue `M7.end − M5.end`, transit `H1.start − M8.end`, ParcelPath intake `P1.start − H1.start` [OR-6] |
| Failed-delivery cost to Mitti | failures × ₹120 [Case rate] |
| Cost of bad addresses | flagged orders × failure rate of flagged orders × ₹120 [OR-12] |
| Expansion revenue | extra orders × ₹50 (ParcelPath); × ₹450 (Mitti sales) [Case rates] |
| Tickets per 1,000 orders | tickets ÷ orders × 1,000 |
| Cost-to-serve gap | avg charge per order vs ~₹50 ParcelPath earns per order [Case] |

### 5.2 RAG thresholds (`config/thresholds.ts`) [Inferred]
| Metric | Green | Amber | Red |
|---|---|---|---|
| On-time | ≥ 90% | 87–89.9% | < 87% |
| Failed | ≤ 7.0% | 7.1–8.5% | > 8.5% |
| Damage /10k | ≤ 15 | 16–20 | > 20 |
| Feed delay | < 15 min | 15–60 min | > 60 min or no orders 10 min on sale day |
| Escalations /month | ≤ 8 | 9–15 | > 15 |
| Ticket ack | within timer | < 25% time left | overdue |

### 5.3 Customer Priority Score (0–100) [Inferred]
```
priority = round( 0.35 * norm(predictedCLV12m)        // percentile among customers, 0–100
                + 0.25 * churnScore                    // low 20, medium 55, high 90
                + 0.25 * currentOrderRisk              // perishable 40 + delay-so-far up to 40 + value>₹450 20
                + 0.15 * (repeatIssue ? 100 : 0) )
```
**Predicted CLV (prototype):** `avgOrderValue × expectedOrders12m × retentionFactor`, where `expectedOrders12m = 12 × ordersPerMonth(last 6m)`, `retentionFactor = 1 − churnProb`, and `churnProb` rises 0.15 for each of the last 3 orders that was late or failed. RFM-style and transparent so the AI explainer can show each factor [CX-AI].

### 5.4 Order criticality (live) [CX-7]
```ts
function criticality(o: Order, c: Customer, now: Date): 'C1'|'C2'|'C3'|'C4' {
  const flags = [
    c.priorityScore >= 75,
    o.items.some(i => i.perishable && daysSinceDispatch(o, now) >= i.shelfLifeDays * 0.7),
    now > new Date(o.promisedBy),
    c.failedCount + c.damagedCount >= 2 /* repeat issue */,
    o.stages.some(s => s.code === 'P12' && s.status === 'failed'),
  ].filter(Boolean).length;
  if (flags >= 2) return 'C1';
  if (flags === 1 || (o.saleDay && cutoffAtRisk(o, now)) || o.newCity) return 'C2';
  if (o.value < 450 && !o.items.some(i => i.perishable)) return 'C4';   // ₹450 AOV [Case]
  return 'C3';
}
```
Recomputed on every stage change and every minute in the prototype clock.

### 5.5 Ticket priority and timers [CX-8, TK-2]
- Severity (by category): 4 = failed delivery dispute, damage, feed delay on sale day, billing dispute; 3 = late delivery, wrong/missing items, stock mismatch; 2 = tracking not updating, address issue, return not processed; 1 = other.
- Criticality weight: C1 = 4, C2 = 3, C3 = 2, C4 = 1.
- **Priority = severity × criticality weight** (1–16). Sorted descending on the board.
- Timers: C1 ack 30 min; C2 ack 1 h; C3/C4 ack 2 h (the **fairness floor**: no ticket gets a timer longer than 2 h ack). Resolve due: C1 4 h, C2 8 h, C3/C4 24 h; billing disputes 48 h [PRD §3.2].
- Overdue ack or resolve → `escalated = true`, account manager notified, badge on Home.

### 5.6 Routing (stage → owner) [CX-8]
| Stage range | Owner side and team |
|---|---|
| M1–M6 | Mitti ops (Imran's team) / Mitti tech for M2 address rules |
| M7–M8, H1 | Mitti tech (sending) or ParcelPath tech (receiving), by which delay segment is larger |
| P1–P10, P14–P15 | ParcelPath warehouse ops (by warehouse) |
| P11–P13 | ParcelPath delivery ops (by city) |
| P7→B1–B2, H3 | ParcelPath billing / Mitti Finance |
A ticket raised by one side routes to the stage owner on the other side.

### 5.7 Billing mismatch check [BL-3, BL-4]
1. `expectedSize` = most common packed size for the same item mix over the last 60 days (min 20 samples), else rule-based from item volume.
2. Flag if `billedSize ≠ expectedSize` **or** `recordedSize ≠ billedSize`.
3. `deltaRs = rate[billed] − rate[expected]`; direction over/under.
4. Pattern detection: group flags by warehouse × station × shift × week; surface any group with flag rate > 3× the overall rate.
5. **Send lock:** `canSend = lines.filter(l => l.flag && !l.review).length === 0 && rateCardConfirmed && totalsReconciled`.

### 5.8 Gate rule [PL-5]
`pass` only if all hold for the last 14 days: new-city on-time ≥ 90%; failed and damage trend `down` or `flat` below target; zero overdue tickets in that city; **existing 6 cities' on-time ≥ 90%** (expansion must not hurt current service). A wave goes live only when `result === 'pass'` and both sign-offs exist.

### 5.9 What-if simulator [PL-9]
```
extraOrders = Σ city.expectedOrders   (default per city = 60,000 / 8 = 7,500 [Case ÷ Inferred even split])
ppRevenue  = extraOrders × 50         [Case]
mittiSales = extraOrders × 450        [Case]
risk = cities > 4 ? 'High (exceeds ops safe limit of 4)' : cities > capacity.remaining ? 'Medium' : 'Low'  [Case limit]
```

## 7. AI integration (Gemini)

**Provider:** Google Gemini API, called only from the backend proxy. **Default model:** `gemini-2.5-flash` for every AI box. **Heavy model:** `gemini-2.5-pro` for 3 tasks (§7.2), with automatic fallback to Flash. **Last resort:** pre-saved answers (§7.8).

### 7.1 Security rules (non-negotiable) [AI-8]
- The Gemini API key lives **only** in a local `.env` file (development) or the host's environment variables (Vercel / Render). It never appears in code, docs, screenshots, chat or the browser bundle.
- `.env` is listed in `.gitignore`. Only `.env.example` (empty values) is committed.
- The browser never calls Gemini directly. No `VITE_`-prefixed key variables, because Vite exposes those to the browser.
- If the key is ever pasted in chat, committed, or shown on screen, **rotate it** in Google AI Studio and update the host variable.
- Proxy limits: whitelist of task names, max context 30 KB, max question 1,000 characters, 20 s timeout per Gemini call, per-visitor rate limit (§7.8).

### 7.2 Model routing
| Model | Tasks | Why |
|---|---|---|
| `gemini-2.5-pro` | `liveops.root_causes` (escalation root-cause analysis) · `planning.gate_advisor` (expansion gate check) · `planning.capacity_check` (optional, switch with `PRO_FOR_CAPACITY=true`) | Multi-step reasoning over many records; these drive gate and fix decisions |
| `gemini-2.5-flash` | All other tasks in §7.5 (briefs, explainers, flags, drafts, summaries, chat) | Fast, cheap, higher rate limits; good enough for grounded short answers |

**Fallback chain** (per request, automatic):
```
Pro  ──(429 rate limit / 503 overloaded / timeout)──▶  Flash  ──(429 / error / timeout)──▶  Pre-saved answer
```
- The response carries `modelUsed` (`pro` | `flash` | `saved`) and the UI shows a small tag ("Answered by Flash: Pro busy" or "Saved answer: AI quota reached").
- A Pro 429 sets a 60 s cool-down, during which Pro tasks go straight to Flash (avoids hammering a limited model).
- A 400 (bad request) or a safety block does **not** fall back to another model; it returns the saved answer with the reason, so a bad prompt is fixed, not hidden.

### 7.3 Endpoint and Gemini call
```
POST /api/ai/:task
headers: { x-access-code?: string }            // only if ACCESS_CODE is set (§7.8)
body:    { window: WindowId, role: Role, question?: string, contextIds?: string[], payload?: object }
200:     { answer: string, items?: object[], sources: string[], draft?: Draft,
           confidence?: 'high'|'medium'|'low', modelUsed: 'pro'|'flash'|'saved' }
401:     { error: 'access_code_required' }
429:     { error: 'visitor_limit', retryAfterMin: number, saved?: {...} }   // saved answer included
```
The server rebuilds the context from the data store using `window` + `role` (it never trusts context sent from the client), then applies `roleFilter` and PII masking.

```ts
// server/gemini.ts  (uses Node 18+ fetch; no key in code)
const KEY   = process.env.GEMINI_API_KEY!;
const FLASH = process.env.GEMINI_MODEL_DEFAULT ?? 'gemini-2.5-flash';
const PRO   = process.env.GEMINI_MODEL_HEAVY   ?? 'gemini-2.5-pro';
const HEAVY = new Set(['liveops.root_causes', 'planning.gate_advisor',
  ...(process.env.PRO_FOR_CAPACITY === 'true' ? ['planning.capacity_check'] : [])]);
let proCooldownUntil = 0;

async function generate(model: string, system: string, user: string, schema?: object) {
  const res = await fetch(
    `https://generativelanguage.googleapis.com/v1beta/models/${model}:generateContent`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json', 'x-goog-api-key': KEY },
      body: JSON.stringify({
        systemInstruction: { parts: [{ text: system }] },
        contents: [{ role: 'user', parts: [{ text: user }] }],
        generationConfig: { temperature: 0.2, responseMimeType: 'application/json',
                            ...(schema ? { responseSchema: schema } : {}) },
      }),
      signal: AbortSignal.timeout(20_000),
    });
  if (!res.ok) throw Object.assign(new Error(`Gemini ${res.status}`), { status: res.status });
  const data = await res.json();
  return JSON.parse(data.candidates?.[0]?.content?.parts?.[0]?.text ?? '{}');
}

const retryable = (e: any) => e.status === 429 || e.status === 503 || e.name === 'TimeoutError';

export async function runTask(task: string, system: string, user: string, schema?: object) {
  if (HEAVY.has(task) && Date.now() > proCooldownUntil) {
    try { return { ...(await generate(PRO, system, user, schema)), modelUsed: 'pro' }; }
    catch (e: any) {
      if (!retryable(e)) return savedAnswer(task, 'error');
      if (e.status === 429) proCooldownUntil = Date.now() + 60_000;
    }
  }
  try { return { ...(await generate(FLASH, system, user, schema)), modelUsed: 'flash' }; }
  catch (e: any) { return savedAnswer(task, e.status === 429 ? 'quota' : 'error'); }
}
// savedAnswer(task, reason) → entry from /server/saved_answers.json + { modelUsed: 'saved', reason }
```
Gemini 2.5 models use built-in "thinking"; Pro is slower (often 10–20 s on large contexts), so Pro tasks show a progress message in the UI (see UI/UX §7.3).

### 7.4 Prompt structure
**System prompt (shared):**
```
You are the operations assistant inside the "{window}" window of the Mitti × ParcelPath platform.
Rules:
1. Answer ONLY from the JSON context provided. If the answer is not in it, say "Not in this window's data."
2. Every claim must cite the IDs of the rows you used in "sources".
3. You only draft. Never say a message was sent, a refund made, a credit issued or a gate approved.
4. Do not invent figures. Use rupee rates only as given in the context (₹120 per failed delivery,
   ₹50 per order to ParcelPath, ₹450 Mitti average order).
5. ParcelPath does not run dark stores or quick delivery, and there are no couriers. Do not suggest them as current services.
6. Plain, short sentences. Indian number format (lakh, crore).
7. Return JSON matching the schema.
```
**Window prompt** adds the window's purpose, the role, and task instructions. **User turn** = `CONTEXT: {json}` + `TASK: {task}` + `QUESTION: {question}`.

### 7.7 Output handling
- Validate JSON against the schema; if invalid, retry once with "Return valid JSON only", then fall back.
- Drop any `sources` ID not present in the context (prevents invented references); if none remain, show "Low confidence: no source rows".
- Anything with a recipient or a money/rule/gate effect is stored as a `Draft` with status `pending` and appears in the approval drawer. **No code path sends or applies a draft without an approver click.**
- Fallback: pre-saved answers in `/server/saved_answers.json` (§7.8), shown with a "Saved answer" tag and the reason (visitor limit, quota, error).

### 7.8 Hosting safeguards
The prototype is **hosted online** so judges and Mitti/ParcelPath stakeholders can open a link. Safeguards protect the key's quota:

| Safeguard | How it works | Config |
|---|---|---|
| **Hosting** | Front end as a static build; `/api/ai/*` as a serverless function (Vercel) or a small Express server (Render). Key set in the host's Environment Variables screen | Vercel: Project → Settings → Environment Variables · Render: Service → Environment |
| **Per-visitor rate limit** | Each visitor gets a random ID in an httpOnly cookie; limit counted per cookie ID **and** per IP (whichever hits first). Default 15 AI requests per rolling hour (range 10–20). Over the limit → HTTP 429 with the saved answer and "Try again in N min" | `AI_RATE_LIMIT_PER_HOUR=15` |
| **Where counts live** | Render (one long-running instance): in-memory map is enough. Vercel (many short-lived instances): use a small KV store (e.g. Upstash Redis) so counts are shared; without it, limits are per instance and only approximate | `KV_REST_API_URL`, `KV_REST_API_TOKEN` (Vercel only, optional) |
| **Optional access code** | If `ACCESS_CODE` is set, the AI panel asks for a code once; the browser sends it as `x-access-code`; the server compares it (constant-time) and returns 401 if wrong. The rest of the dashboard (sample data) stays open. The code is never in the front-end bundle | `ACCESS_CODE=` (leave empty to switch off) |
| **Pre-saved fallback answers** | `/server/saved_answers.json` holds one good answer per task × window, written in advance from the seeded data (so they stay accurate to the demo). Served when the visitor limit, Gemini quota or an error stops a live answer. Always tagged "Saved answer" | Built by `scripts/save-answers.ts` (runs each task once with the key, then saved) |
| **Global daily cap** (extra) | Stops all live calls after N requests per day, protecting the free-tier quota during a demo day | `AI_DAILY_CAP=500` |
| **No logging of secrets or PII** | Logs keep task, model used, latency, status code and IDs only | n/a |

Steps:
1. Copy `.env.example` to `.env` and paste the key after `GEMINI_API_KEY=` **in that file only**. Check `.gitignore` contains `.env`.
2. Run locally: `npm install` → `npm run dev` (front end and `/api` together). The server reads `.env` through `dotenv`.
3. Deploy: push the repo (without `.env`), then add the same variables in Vercel or Render's environment settings and redeploy.
4. Check: open the deployed site, view page source / built JS and search for the key. It must not be there. Ask an AI box a question and confirm the "Answered by Flash/Pro" tag.

## 8. Front-end behaviour
- **Prototype clock:** "today" runs on a simulated clock (play / pause / ×10 speed) so stages, timers and the 7 PM feed spike can be shown live.
- **Role switcher** re-renders all windows through `roleFilter` selectors; hidden windows show a lock card ("Not available for Mitti Finance").
